# 第一部分：APP整体需求

## 1. APP定位

本 APP 是一款仅供个人使用的考研学习管理与智能复习 APP，运行于个人 Redmi Pad Pro 平板设备，不面向其他用户，不上架，不提供服务器及云端服务。

APP 主要用于管理数学、408、英语、政治等考研学习内容。

APP 核心由以下部分组成：

- 学习内容管理

- 图片错题本

- 知识点管理

- 自动间隔复习

- 错题/专项刷题

- 学习统计

- 数据备份与恢复

核心目标不是单纯提醒用户复习，而是：

- 用户负责学习、做题和回忆

- APP 负责保存学习内容

- APP 负责记录学习状态

- APP 根据复习表现自动安排后续复习

- 用户可以按照自己的需求进行专项刷题

APP 定位为：

个人学习资料库 + 自动复习工具 + 错题专项训练工具

## 2. 使用范围

- 仅供本人使用

- 仅运行于 Redmi Pad Pro

- 不考虑多用户

- 不考虑账号系统

- 不考虑服务器

- 不考虑云数据库

- 不考虑云端同步

- 不考虑多设备同步

- 不考虑网页端

- 不考虑桌面端

- 不考虑后续大型功能扩展

## 3. 核心数据

APP 主要管理以下数据：

- 习题

- 知识点

- 笔记

- 学科

- 板块

- 章节

- 图片

- 标签

- 错题

- 收藏

- 掌握程度

- 难度

- FSRS 状态

- 复习记录

- 错误原因

- 专项刷题方案

- 专项刷题记录

- 完整备份数据

## 4. 核心使用流程

日常学习：

做题 → 拍照/截图 → 快速添加 → 选择分类 → 设置红黄绿 → 设置是否错题 → 保存

系统复习：

打开 APP → 今日复习 → 做题/回忆 → 查看答案 → Again / Hard / Good / Easy → APP 自动安排下一次复习

主动刷题：

进入专项刷题 → 设置筛选条件 → 设置题量和排序 → 开始刷题 → 做题 → 查看答案 → 记录结果 → 查看总结

长期管理：

每天学习 → 自动复习 → 专项刷题 → 统计错误 → 查看薄弱章节 → 定期完整备份

## 6. 掌握程度系统

每条学习内容设置主观掌握程度：

红色：不稳定

- 基本不会

- 容易忘

- 经常做错

- 需要频繁复习

黄色：会一些

- 大概会

- 能做但不稳定

- 有时需要提示

- 容易出现错误

绿色：很稳定

- 掌握比较牢

- 基本能够独立完成

- 很少出错

红黄绿由用户自己设置，不等同于 APP 自动复习算法。

- 取消错题

曾经是错题，不代表当前一定高风险。

## 13. 自动复习

采用动态间隔复习算法，根据实际复习表现自动决定下一次复习时间，而不是固定间隔。

## 14. 今日复习队列

根据当前复习状态生成今日待复习内容。

优先考虑：

- 高风险内容

- 严重逾期内容

- 红色内容

- 稳定性低的内容

排序不能破坏原有复习算法状态。

## 15. 复习负担控制

用户可以设置：

- 每日复习上限

- 每日新增内容上限

超过上限的内容不能删除，只能保留为待处理内容。

## 16. 高风险系统

高风险由 APP 自动判断。

综合考虑：

- 红黄绿状态

- FSRS 稳定性

- 是否严重逾期

- 最近连续错误次数

- Again 次数

- 历史错误次数

- 最近刷题表现

风险等级：

- 低风险

- 中风险

- 高风险

- 极高风险

用途：

- 首页重点提醒

- 今日复习优先级

- 专项刷题筛选

- 统计分析

## 17. 错误原因记录

- 概念不会

- 计算错误

- 粗心

- 高风险

排序

- 随机

- 最久没有做

- 错误次数最多

- 最不稳定

- 最近添加

手动选择

允许进入具体章节后手动勾选指定题目进行刷题。

保存刷题方案

可以保存筛选条件、题量、排序方式等。

## 19. 专项刷题过程

显示题目 → 用户做题 → 查看答案 → 评价结果

- 错误

- 有点困难/犹豫

- 跳过

- 做题耗时

可以设置：

将本次刷题表现计入复习系统

开启后，本次刷题表现才影响自动复习。

# 第三部分：UI/交互需求

- 以个人高频使用为核心

- 操作流程尽量简单

- 录入速度优先

- 减少重复操作

- 重要操作提供明确反馈

- 删除等危险操作必须二次确认

- 图片操作适配平板触控

- 不增加社交型、商业型功能

# 第四部分：数据库设计

## 1. 数据库技术

采用：

SQLite + Drift

SQLite 负责本地持久化数据，Drift 负责 Flutter/Dart 与 SQLite 的数据访问。

APP 为单用户、单设备、本地数据库，不使用 MySQL、PostgreSQL、Firebase、服务器数据库等。

# 第五部分：FSRS设计

## 1. FSRS定位

FSRS 是 APP 的自动间隔复习核心。

系统根据用户实际复习表现动态计算下一次复习时间，不使用固定的：

1天、3天、7天、14天……

## 2. 新内容首次复习

根据用户创建内容时设置的红黄绿状态：

|掌握程度|初始复习时间|
|---|---|
|红色|约1天后|
|黄色|约3天后|
|绿色|约7天后|

这只是新内容首次进入复习系统时的初始安排。

正式复习后，由 FSRS 根据实际表现动态调整。

## 3. 正式复习流程

显示题目

↓

用户自己思考/做题

↓

查看答案

↓

用户进行评价

↓

Again / Hard / Good / Easy

↓

FSRS计算下一次复习时间

↓

保存FSRS状态

↓

保存复习记录

## 4. 评价等级

Again

完全不会、忘记、做错。

Hard

想起来了，但是困难很大。

Good

正常回忆、正常做出。

Easy

非常熟练。

## 5. 下一次复习时间

用户评价时，可以提前看到不同评价对应的预计下次复习时间。

具体时间由 FSRS 动态计算。

## 6. FSRS状态保存

每条进入复习系统的学习内容需要保存：

- 下一次到期时间

- 稳定性

- FSRS内部难度

- 当前状态

- 复习次数

- Again次数

- 上一次复习时间

- 当前计划间隔

## 7. FSRS与红黄绿的关系

红黄绿：

用户主观掌握程度

FSRS：

根据实际复习表现计算的动态状态

两者不能混为一体。

## 8. FSRS与错题的关系

错题状态独立存在。

一道题以前是错题，但经过多次正确复习后：

仍然可以保持“错题”标记，但当前不一定属于高风险。

## 9. FSRS与专项刷题的关系

默认情况下：

专项刷题不修改 FSRS。

用户可以选择：

将本次刷题表现计入复习系统

开启后，本次表现才影响自动复习。
